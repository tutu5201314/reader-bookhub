# bookhub v1.0.0 — 稳定版

把「能搜到书」变成「能稳定读完一本书」。

这一版不含新功能，全部是**正确性、吞吐、容量、解析鲁棒性**的修补：22 项修复，99 条单测，一次 1864 章的整本压测。

---

## 一、数据正确性（会毁掉缓存的三处，已全部堵死）

| 问题 | 现象 | 修法 |
|---|---|---|
| 章节缓存非原子写 | 写到一半被杀 → 缓存文件残缺，之后永远读到半章 | 写 `.tmp` 再 `os.replace` |
| 分页中断仍落盘 | 正文分页第 2 页超时，第 1 页被当成完整章节缓存 | 中断即返回但不落缓存，下次重读自愈 |
| 损坏缓存无自愈 | 已有 <50 字的缓存文件被当成有效内容 | 读到时判短即删，重新抓 |

附带修掉 `_refreshing: true` 被持久化的问题——进程在后台追更时被杀，这个字段会写进 `data/books/{id}.json`，重启后这本书**再也不会自动追更**。现在落盘前过滤下划线开头的临时字段。

## 二、吞吐（搜索 26s → 4.9s，60 条结果）

| 问题 | 根因 | 修法 |
|---|---|---|
| 14 站并发被压成 1.6 req/s | 节流用实例级 `self.last`，全局 0.6s | 改按 host 计时 + 先占位再睡 |
| L3 真浏览器串行排队，最长 25s+10s | 单个 ChromiumPage + 全局锁 | 改标签页池（POOL_SIZE=2），取不到 tab 就降级不阻塞 |
| 体检逐本串行 | `for` 循环里三章实抓 | `ThreadPoolExecutor(4)` + `as_completed` |
| SSE 搜索固定等 45s | `as_completed(timeout=45)` 硬等 | `wait(FIRST_COMPLETED)` 轮询 + 60s 总预算，拿到一个推一个 |

## 三、容量与可观测

- **章节缓存配额**：默认 500 MB，启动时按「最久未读整本」清理，`GET /api/cache/stats` 可查（实测 8.5 KB/章，1864 章 ≈ 16 MB）
- **后台任务回收**：`JOBS_TTL=1800` / `JOBS_MAX=20`，任务记录不再无限堆积（原实现只增不减）
- **结果上限可调**：`?limit=0~300`，网页台「显示更多」按钮，配置项 `max_results`

## 四、解析鲁棒性（换源时踩出来的坑）

- **目录分页只翻 20 页**：写死 `range(20)`，每页 20 章的书最多 400 章。1864 章的书第一次只解析出 430 章。改为 300 页 + 300 秒预算 + 进度日志
- **目录乱序**：站点「首页倒序 + 后续页正序」混排。新增 `sort_chapters_by_num()`，用**最长递增子序列（LIS）占比 ≥90%** 判断「这本来就是一本几乎有序的目录，只是少量条目错位」再重排；分卷重编号的书 LIS 只有 ~45%，自动跳过（《大日金乌纵横诸天》就是这种，按号排会毁掉正文顺序）
- **水印误杀**：`^\d{1,4}$` 和 `#.*#.*#` 两条规则会把正文里的裸数字行、`#` 分隔行当广告删掉。改为「裸数字只在首尾 3 行删」「`#` 行需命中语义词」
- **mojibake 误判**：无 `<title>` 或 title 是 ASCII 的中文页会被整体按 Latin-1 误解，「下一页」锚点变乱码，正文分页永远找不到。增加 body 前 5 个文本节点做二次判断
- **`第268（2）章` 分节写法**：`_chap_num` 返回 None 会导致整本书放弃排序

## 五、体检不再只会说「站点不可达」

新增 `LayeredFetcher.diagnose()`，把布尔式探活换成**分级诊断**：

| 站 | 修前 | 修后 |

三态灯：🔴 目录都拿不到 / 🟡 目录有但正文取不到（缓存仍可读）/ 🟢 正常。

## 已知限制

1. **headless 过不了 Cloudflare Turnstile** —— 69shuba / ddxs / shanyuread 这类站永久排除，真 Chrome 等 31 秒也不放行
2. **目录排序的 LIS 闸门** —— 只对「几乎有序、少量错位」的目录重排；真·交错目录（LIS <90%）保持原样，宁可乱也不乱排
3. **`reader_dir` 默认指向项目内 `books/`** —— 不是 Reader 真实书库目录，txt 导出会落到项目里，请按需修改 `config.json`
4. **投毒站只能事后发现** —— 目前靠人工抽查中间章，没有自动的「跨章内容一致性校验」
5. **长跑时目录可能被 TTL 刷新改写** —— 压测跑到第 30 分钟时 `get_catalog` 的 1800s TTL 到期，后台重新 resolve 换掉了 9 个章节的 URL（站点改过链接），这 9 章缓存键随之失效、需重抓。没有数据损坏，但说明超长连续抓取时缓存命中率会掉一点

## 升级说明

1. 覆盖代码后重启（`bookhub.bat`）
2. `config.json` 新增两个可选键：`max_results`（默认 60）、`cache_max_mb`（默认 500），不写就用默认值
3. 种子站少了一个（天空书屋投毒停用），首次搜索会比之前快一点
4. 若之前有书是天空书屋的源，建议换源
